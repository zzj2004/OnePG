# 立项文档 —— 代号 OnePG

日期：2026-09-04 ｜ 阶段：前期立项完成，进入原型设计（技术选型） ｜ 状态：剩 1 项待确认（见第 10 节）

## 1. 一句话定位

一款网页版的 2D 平台格斗游戏：把对手打出场外获胜，朋友点开链接就能玩，无需安装任何东西。

## 2. 项目目标

- 最高优先级：自己和朋友玩着开心
- 练手学习：走完"想法收敛→立项→原型→开发→测试上线"完整流程
- 近期分发：GitHub 开源 + 网页版（GitHub Pages）+ **U 盘便携版**（拷进优盘，机房电脑双击就能玩）
- 远期（品质达标后）：上架 PC / 安卓 / 苹果商店——技术路线从第一天为此留门

## 3. 非目标（明确不做的）

- 不做跨公网联机（只做同一 WiFi / 局域网）
- 不做 Flash 或任何需要安装客户端的形式
- 不做随机搞怪道具/机关陷阱（Brawlhalla 里 gadgets 那类）
- 角色专属武器系统**要做**（用户已确认，属核心战斗内容而非欢乐道具，详见 4.3）
- 第一版不做 4 人混战（架构上预留人数，功能后置）

## 4. 核心玩法（已收敛的设计决定）

### 4.1 胜负规则（用户已确认：要"打出场"的爽感）

- 没有血条。角色受到的伤害越多，被击飞得越远
- 场地是"孤岛"：主平台 + 浮空平台，平台之外是深渊
- 被打出场外且跳不回来 = 死，扣一条命；用完命数则输掉比赛

### 4.2 对战模式

- **第一版只做 1v1**：每人 3 条命，最多选 3 个角色，每死一次可换下一个角色上场（借鉴 Brawlhalla 的三命换英雄）
- 多人混战（FFA）：后置
- 对局时长有界（命数封顶）；自定义房间可调参数（出招/移动速度、倒计时开关等）后置

### 4.3 角色与武器

- 每个角色独立的技能组
- **武器系统（用户已确认，借鉴 Brawlhalla）**：每个角色有"空手"和"专属武器"两套招式；武器在场地中刷新、可拾取、可被打落；手持专属武器时发挥最大效果。首版 2 角色 = 4 套招式
- 招式数据驱动：加角色 = 填数据，不重写代码（架构保证）
- 第一版角色数量：**2 个（已定）**

### 4.4 操作

- 键盘为主，键位完全可自定义
- 下平台提供操作方案选择（用户习惯：下方向键+空格 = 下穿平台，单击空格 = 跳跃）
- 转向必须跟手——Brawlhalla 转身僵硬是用户明确不喜欢的点，我们要避开
- 蓄力期间**允许转向（已定）**——与 Brawlhalla 的差异点，平衡性到 M1 验证

### 4.5 打击感（全游戏最高设计优先级）

用户反馈"打击感最爽"。顿帧、震屏、粒子、音效从 M1 起持续投入，M4 集中强化。

## 5. 从 Brawlhalla 借鉴 / 刻意不同

- **借鉴**：孤岛场地+深渊出界死、伤害换算击飞、三命换英雄、平台跳跃/下穿、房间自定义参数
- **刻意不同**：转向跟手；蓄力可转身。上手难度**对齐 Brawlhalla、不降档（用户已定，原话："强者去适应环境，弱者去换环境，菜就多练"）**——代价是"训练模式"进后置功能清单，让"菜就多练"有地方练

## 6. 技术选型（已定 2026-09-04：方案 A）

**方案 A：自研薄引擎 —— TypeScript 语言 + PixiJS（开源绘图库）+ 自研确定性战斗核心**（"踩在巨人的肩膀上造轮子"：TypeScript/PixiJS/构建工具全是开源生态，战斗核心自己写）

- **核心原则：固定步长（60 帧/秒）确定性模拟**——同样的按键序列在任何电脑上算出完全一样的对战过程。这是"联机只传按键、延迟极低"的地基，也让战斗逻辑可以写自动化测试
- **分发形态（同一份代码，多个出口）：**
  1. 网页版：GitHub Pages 托管，点链接即玩
  2. **U 盘便携版**：打包成单个 HTML 文件，拷进优盘，机房电脑双击用浏览器打开即玩，免安装
  3. 远期商店版：核心逻辑与平台解耦（输入/渲染走抽象层），届时用 Tauri/Electron 打包 PC 版、Capacitor 打包手机版（先例：《吸血鬼幸存者》即网页技术起家、上架全平台）
- 联机：局域网房间号方案——公共服务撮合握手（需联网），实际对战数据局域网直连
- 已知局限（如实记录）：浏览器安全限制，网页无法自动发现局域网设备——**完全断网**的两台电脑无法自动联机（单人/同键盘双人不受影响）
- 否决项：Godot（网页包体大、物理无确定性保证、可视化编辑器在"我写码你试玩"分工中用不上）、Unity（更重）
- 质量方针（用户定调"慢工出细活，不怕慢就怕差"）：确定性模拟+自动化测试覆盖战斗逻辑；每个里程碑用户实机验收；不赶进度

## 7. 分工

- 用户：手感最终裁判、高频试玩反馈、角色/玩法创意、各里程碑验收
- 我：全部代码、系统/数值设计、占位美术（几何小人+程序动画）、文档和开发工具

## 8. 里程碑与验收标准

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| M0 白盒原型 | 两个色块小人，跑/跳/二段跳/下穿平台/击飞出界判负，本地双人 | 用户试玩认可"手感好玩" |
| M1 战斗系统 | 攻击/受击/防御闪避/伤害击飞换算、1 个测试角色、简单 AI | 能完整打赢一局人机 |
| M2 内容 | 2 个角色（各自空手+专属武器，共 4 套招式）+ 1~2 张地图 + 菜单/选人/对局/结算流程 | 朋友完整玩一局不会问"然后呢" |
| M3 联机 | 局域网 1v1 + GitHub Pages 可访问 | 两台设备同 WiFi 对战，体感延迟可接受 |
| M4 升级 | 打击感特效、音效、（可选）第 3 角色、房间自定义参数 | 用户认为"值得发给朋友" |

## 9. 风险清单

- **美术是我的短板**：占位美术保证能跑通；"好看"靠 M4 素材库/外包/社区合作
- **手感迭代依赖真人试玩**：M0 起需要用户高频试玩，我无法替用户感受手感
- **联机是最大技术风险**：所以放在 M3，核心玩法成立后才投入
- **范围膨胀**：任何新想法先进"非目标/后置"清单，不进当前里程碑

## 10. 决议与待确认

**已定（2026-09-04）：**
1. 蓄力期间允许转向（平衡性 M1 验证）
2. 首版角色 2 个
3. 上手难度对齐 Brawlhalla，不降档；训练模式进后置清单
4. 游戏名先用代号 **OnePG**（One People Game）
5. 武器系统采纳：专属武器模式（见 4.3）；随机搞怪道具不做

**待确认（唯一遗留）：**
